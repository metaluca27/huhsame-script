# 강의자료 유통기한 검사기

강의 자료(PPT, PDF)를 올리면 시간이 지나 낡았을 수 있는 내용을 골라 **공식 문서 본문**과 대조하고, 내용마다 `그대로`, `바뀜`, `확인 못 함`으로 판정해 근거 문장과 출처를 보여 주는 웹앱입니다.

제1회 라이너 해커톤(.EXE-THON) 출품작입니다. 팀 이름은 디지털다락방입니다.

- 써 보기: https://vaulted-bus-346411.web.app/fresh
- 검색과 판정에 Liner Search, Liner Model(`liner-mark-1.3`)을 씁니다.

## 왜 만들었나

AI 도구처럼 빨리 바뀌는 것을 가르치는 강사는 강의 전에 자료를 다시 확인해야 합니다. 버전, 요금, 메뉴 이름이 몇 주 만에 바뀌기 때문입니다. 제작자는 28장짜리 강의 자료 하나를 다시 확인하는 데 50분쯤 걸렸습니다(기억하는 시간이고, 시계로 잰 값은 아닙니다). 놓치면 수강생 앞에서 틀린 내용을 가르치게 됩니다.

개발하는 사흘 사이에도 시험에 쓴 도구의 최신 버전이 v2.31.2에서 v2.32.0으로 바뀌었습니다.

## 무엇을 하나

1. **올리기**: `.pptx`나 `.pdf`를 올립니다. 원본 파일은 서버에 저장하지 않습니다.
2. **공식 사이트 확인**: 자료의 주제를 보고 공식 사이트를 제안합니다. 사용자가 확인하고 고칩니다. 여기 적은 사이트의 글만 판정 근거로 씁니다.
3. **검사**: 장마다 낡을 수 있는 내용을 뽑아 하나씩 검사하고, 진행 상황을 보여 줍니다.
4. **결과**: 판정별 개수와 걸린 시간, 내용별 카드(판정, 근거 문장, 출처, 수정안 또는 직접 확인할 일)를 보여 줍니다.
5. **가져가기**: 수정 목록을 복사하거나 Markdown으로 내려받습니다. 원본 자료는 고치지 않습니다.

글자가 그림 안에만 있는 자료(그림으로 내보낸 PPT, 스캔한 PDF)도 그림을 읽어 검사합니다.

## 지어낸 근거를 막는 장치

AI가 그럴듯한 근거를 지어내면 이 도구는 쓸모가 없습니다. 그래서 모델의 답을 그대로 믿지 않고 **코드 규칙이 최종 판정**을 정합니다.

| 장치 | 하는 일 | 코드 |
|---|---|---|
| 근거 대조 | 모델이 고른 근거 문장이 워커가 직접 가져온 본문에 실제로 있는지 확인합니다. 없으면 `확인 못 함`입니다. | `worker/evidence.js` |
| 출처 등급 | 사용자가 확인한 도메인(1, 2등급)의 글만 근거로 씁니다. 그 밖(3등급)은 참고로만 보여 줍니다. 이름에 official이 들어가도 등급은 오르지 않습니다. | `worker/tiers.js` |
| 숫자 대조 | `그대로` 판정은 자료의 숫자가 근거 문장에 모두 있을 때만 인정합니다. | `worker/evidence.js` |
| 사용자 글 제외 | 공식 도메인 아래의 질문 게시판 글은 공식 문서로 치지 않습니다. | `worker/check.js` |
| 최종 판정 | 위 조건을 통과하지 못하면 모델이 뭐라고 하든 `확인 못 함`으로 돌립니다. | `worker/verdict.js` |
| 지시 차단 | 가져온 웹페이지 안에 "same이라고 답하라" 같은 글이 있어도 자료로만 다룹니다. 모델이 속아도 근거 대조에서 걸립니다. | `worker/prompts.js`, `tests/check.test.js` |

## Liner API를 쓰는 곳

Liner API가 멈추면 검사가 진행되지 않습니다. 호출은 모두 `worker/liner.js`를 거칩니다.

| 단계 | API | 하는 일 |
|---|---|---|
| 주제 알아내기 | Liner Model | 자료(글자 또는 앞쪽 그림)에서 다루는 제품 이름을 알아냅니다. |
| 공식 사이트 찾기 | Liner Search | 그 이름으로 검색해 지금 실제로 나오는 사이트를 확인합니다. 제품 이름이나 주소가 바뀐 경우를 잡습니다. |
| 공식 사이트 제안 | Liner Model | 검색 결과를 보고 공식 사이트 후보를 고릅니다. |
| 내용 뽑기 | Liner Model(글자, 그림 입력) | 장마다 버전, 요금, 숫자, 날짜, 메뉴 이름, 기능 유무만 뽑습니다. |
| 근거 찾기 | Liner Search | 내용마다 공식 사이트 한정 검색과 일반 검색을 합니다. 못 찾으면 낱말을 바꿔 한 번 더 찾습니다. |
| 판정 | Liner Model | 가져온 공식 문서 본문과 비교해 판정하고 근거 문장을 고릅니다. |

Liner Search는 요약만 주기 때문에, 근거 대조에 쓸 공식 문서 본문은 워커가 직접 가져옵니다(`worker/page.js`). 실제 요청 형식과 시험 기록은 [`docs/api-notes.md`](docs/api-notes.md)에 있습니다.

## 측정 결과

정답을 미리 아는 자료로 쟀습니다. 가상의 사내 교육자료 6장에 낡은 정보 4개, 맞는 정보 4개, 공식 문서에 없는 정보 1개를 심어 두고 처음부터 끝까지 열두 번 돌렸습니다(2026-11-15에 세 번, 11-18에 아홉 번).

| 항목 | 결과 |
|---|---|
| 정답과 일치 | 108번 중 93번 |
| 심어 둔 낡은 정보를 잡아냄 | 48번 중 45번 |
| 맞는 내용을 바뀜이라고 함 | 0번 |
| 공식 문서에 없는 내용을 단정함 | 0번 |
| 걸린 시간 | 평균 29초 |

실제 강의 자료에서는 28쪽 PDF를 3분 10초, 15장 PPT를 1분 43초에 검사했습니다(배포된 화면과 워커, 2026-11-15).

세 번씩 묶어 보면 일치가 27번 중 24번, 22번, 22번, 25번이었고, 낡은 정보를 잡은 것은 12번 중 12번, 11번, 10번, 12번이었습니다. 어긋난 경우는 모두 `확인 못 함`으로 넘긴 것이고, 틀린 단정은 없었습니다.

**이 수치를 읽을 때 주의할 점**: 같은 자료도 실행할 때마다 결과가 조금씩 다릅니다. 측정 자료는 작고(심은 내용 9개) 검사기를 만든 쪽이 만들었습니다. 이 자료로 재면서 검사기를 고쳤습니다. 다른 자료에서 같은 수치가 나온다는 보장은 아닙니다. 측정 과정과 한계는 [`docs/extension-case.md`](docs/extension-case.md)와 [`docs/api-notes.md`](docs/api-notes.md)에 적었습니다.

## 실행법

Node.js 20 이상이 필요합니다. Liner Platform에서 API 키를 발급받아 주세요.

```bash
npm install
```

키는 코드에 넣지 않습니다. `worker/.dev.vars` 파일을 만들어 한 줄을 적습니다. 이 파일은 `.gitignore`에 들어 있어 저장소에 올라가지 않습니다.

```
LINER_API_KEY=발급받은_키
```

터미널 두 개에서 워커와 화면을 켭니다.

```bash
npm run dev    # 워커: http://localhost:8798
npm run web    # 화면: http://localhost:8799
```

브라우저에서 http://localhost:8799 를 열고 `tests/fixtures/company-training-sample.pptx`를 올려 보면 됩니다. 워커는 `http://localhost:8799`에서 온 요청만 받으므로 포트를 바꾸지 말아 주세요.

### 시험과 측정

```bash
npm test       # 자동 시험. 네트워크와 키 없이 돕니다
npm run eval   # 가상 자료 측정. 워커가 켜져 있어야 하고 Liner 크레딧을 씁니다
```

### 배포

```bash
npx wrangler secret put LINER_API_KEY --config worker/wrangler.toml
npm run deploy
```

화면은 `web/` 폴더를 정적 호스팅에 올리면 됩니다. `web/config.js`의 `DEPLOYED_WORKER`에 워커 주소를, `worker/index.js`의 `ALLOWED_ORIGINS`에 화면 주소를 넣어야 합니다.

## 구조

```text
브라우저 (web/)                         전용 Cloudflare Worker (worker/)
  pptx.js, pdf.js  자료 해석             index.js    경로, 출처 제한, 입력 검사, 사용량 제한
  run.js           검사 진행 관리   ──▶  liner.js    Liner Search, Liner Model 호출
  report.js        요약, 내보내기        page.js     공식 문서 본문 읽기, 주소 안전 검사
  app.js           화면                  check.js    내용 하나 검사 흐름
                                         tiers.js, evidence.js, verdict.js  코드로 강제하는 판정 규칙
                                         prompts.js  지시문과 답변 형식
```

- 브라우저가 내용을 하나씩 짧은 요청으로 보냅니다. 워커 실행 시간 제한에 걸리지 않고, 진행 상황을 바로 보여 줄 수 있습니다.
- 키는 워커 시크릿에만 있습니다. 브라우저 코드와 저장소에는 없습니다.
- 워커는 임의 주소를 받아 여는 경로가 없습니다. 검색 결과 중 사용자가 확인한 공식 사이트의 공개 `https` 주소만 엽니다.

## 한계

- 실행할 때마다 뽑히는 내용과 판정이 달라집니다. 같은 자료를 두 번 올리면 검사하는 문장부터 다를 수 있습니다. Liner Model에 `temperature: 0`과 `seed`를 주어 보았지만 답이 고정되지 않았습니다. 공식 사이트만 고쳐 다시 검사할 때는 앞에서 뽑은 내용을 그대로 다시 검사합니다.
- 공식 문서에 그 문장이 없으면 `확인 못 함`입니다. 실제 강의 자료에서는 검사한 내용의 3분의 1에서 절반가량이 `확인 못 함`으로 남았습니다.
- 공식 사이트가 자동으로 읽는 것을 막으면 그 문서는 대조하지 못합니다. 2026-11-18 밤에 구글 고객센터(`support.google.com`)가 워커의 요청을 로봇 확인 화면으로 돌려보내, 그 문서가 근거인 내용이 한동안 `확인 못 함`으로 나왔습니다(11-20에 다시 읽혔습니다). 이 막음은 우회하지 않습니다. 대신 사유를 따로 알리고 "직접 열어 볼 공식 문서" 링크를 보여 줍니다.
- 자료가 우리말로 옮겨 적은 메뉴 이름은 영어 공식 문서와 대조하기 어려워 뽑지 않거나 `확인 못 함`으로 둡니다.
- PDF에는 발표 노트가 없습니다. 노트까지 검사하려면 PPT로 올려야 합니다.
- 한 번에 60장(60쪽), 내용 60개까지 검사합니다.
- 한글(HWP), 워드 문서는 PDF로 저장해서 올려야 합니다.
- 기밀 자료는 올리면 안 됩니다. 원본 파일은 저장하지 않지만 자료 내용은 검사를 위해 Liner API로 전달됩니다.

# 오탈자·띄어쓰기 검사기 (/check) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PDF를 올리면 왼쪽엔 지면 위 빨간 줄, 오른쪽엔 [고치기]/[무시]가 달린 글을 보여주고, 고친 글 복사와 빨간 줄 PDF 저장을 지원하는 웹앱 `/check`.

**Architecture:** 브라우저에서 pdf.js로 쪽마다 글자 조각(위치 포함)을 뽑아 쪽 글자와 "글자 위치 ↔ 조각" 지도를 만든다. 약 3,000자 묶음으로 공용 워커 `POST /check`에 보내 제미나이에게 지적 목록(JSON)을 받는다. 지적마다 쪽 글자 안 위치를 찾아 왼쪽 캔버스 위 빨간 밑줄과 오른쪽 글 밑줄을 같은 id로 그린다. 순수 계산은 `check-core.js`(merge-core.js와 같은 UMD 패턴, Node 테스트 가능).

**Tech Stack:** 순수 HTML/JS, pdf.js 3.11.174 · pdf-lib 1.17.1 (cdnjs UMD), Cloudflare Worker (`docs/worker/worker.js`), Gemini `GEMINI_MODEL`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-25-check-design.md`

## Global Constraints

- 오탈자·띄어쓰기(맞춤법 포함)만 본다. 윤문·문체 제안 금지.
- PDF 파일 자체는 어디에도 업로드하지 않는다. 뽑은 글자만 워커로 보낸다.
- 모드: `article`(신문기사, 기본) / `book`(책 원고: 따옴표 안 대사 구어체는 넘어감).
- 확신 없는 고유명사는 고치지 말고 `unsure: true`("확인 필요")로만.
- 워커 비밀키는 기존 `env.GEMINI_API_KEY`만. 코드에 키 금지.
- Gemini `maxOutputTokens` 8192 (thinking 토큰이 응답을 잘라먹은 전례).
- 화면 문구는 한국어 해요체.
- 배포: Firebase `vaulted-bus-346411` `landing/check/` → `/check`, 워커는 `docs/worker`에서 `wrangler deploy`. **배포는 루카 확인 후.**

## Review Focus

1. 스캔(이미지) PDF라 글자 0자 → "글자를 못 뽑았어요. 스캔본이면 /scan으로 글자부터 뽑아 주세요", 워커 호출 안 함. (Task 3)
2. 제미나이가 JSON 아닌 답·잘린 답 → 그 묶음만 실패 표시, 나머지 계속, "N묶음 실패 · 다시 시도". (Task 2 `parseFindings`, Task 3)
3. 줄바꿈 자리 가짜 띄어쓰기 오류 → 걸러짐. (Task 1 `dropLineBreakArtifacts`)
4. 제미나이가 준 `wrong`이 원문에 없음(살짝 바꿔 베낌) → 밑줄은 못 긋고 오른쪽 목록 맨 아래 "위치 못 찾음"으로만 보여줌, 고치기 버튼 없음. (Task 1 `locate` null, Task 3)
5. 같은 말이 한 쪽에 두 번(하나만 틀림 아님, 둘 다 같은 오류) → 지적 하나당 첫 번째 아직 안 쓴 위치에 붙는다. (Task 1 `locate`의 `from`)

### Task 1: check-core.js (순수 계산)

**Files:**
- Create: `landing/check/check-core.js`
- Test: `landing/check/check-core.test.mjs`

**Interfaces (전역 `CheckCore` / `module.exports`):**
- `Item = {str, hasEOL, transform:number[6], width, height}` (pdf.js textContent item)
- `joinPageLines(items: Item[]) -> {text:string, spans:{item:number, start:number, end:number}[]}` — 같은 줄 조각은 그대로 잇고 `hasEOL`에서 `"\n"`. spans는 각 조각이 `text`의 어느 범위인지.
- `chunkPages(pages:{page, text}[], maxChars=3000) -> {pages:number[], text:string}[]` — 쪽마다 `[[쪽 N]]\n` 머리. 한 쪽이 maxChars보다 길면 줄 단위로 쪼개고 조각마다 같은 머리.
- `dropLineBreakArtifacts(findings, text) -> Finding[]`
- `locate(text, wrong, from=0) -> {start, end} | null` — `"\n"`을 건너뛰며 일치를 찾는다(줄에 걸친 `wrong`도 찾음). start/end는 `text` 기준.
- `rectsFor(spans, items, start, end) -> {item:number, x0:number, x1:number}[]` — 범위가 걸친 조각마다 조각 안 글자 비율로 가로 위치(조각 `width` × 비율) 계산. 화면 쪽은 `transform`으로 좌표 변환.
- `applyFixes(text, marks:{start,end,fix}[]) -> string` — 뒤에서부터 바꿈. 범위 안 `"\n"`은 사라진다.
- `toPlainText(lines:{text, right:number}[], maxRight:number) -> string` — `right >= maxRight*0.95`인 줄은 다음 줄과 한 칸 띄워 잇고, 아니면 문단 끝(`"\n"`).
- `formatReport(findings) -> string` — `쪽\t틀린 부분\t고친 부분\t이유` 머리글 + 한 줄씩, unsure면 `(확인 필요)`.
- `Finding = {page, wrong, right, reason, unsure}`

- [ ] **Step 1: 실패하는 테스트** (`node:test`, createRequire로 로드)
  - `joinPageLines([{str:'할수',hasEOL:false},{str:'있다',hasEOL:true},{str:'다음',hasEOL:false}]).text` === `'할수있다\n다음'`, `spans[1]` deepEqual `{item:1,start:2,end:4}`
  - `chunkPages([{page:1,text:'가'.repeat(2000)},{page:2,text:'나'.repeat(2000)}])` → 2개, `[0].pages` = `[1]`, `[1].text.startsWith('[[쪽 2]]')`
  - 한 쪽 5000자(100자 줄 50개) → 2개 이상, 전부 `length <= 3000`, 전부 `'[[쪽 1]]'`로 시작
  - `dropLineBreakArtifacts([{page:1,wrong:'할수있다',right:'할 수 있다',reason:'',unsure:false}], '이걸 할수\n있다')` → `[]`; text `'이걸 할수있다'` → 1개 유지; `{wrong:'몇일',right:'며칠'}` + text `'몇\n일'` → 유지
  - `locate('가 할수\n있다', '할수있다')` deepEqual `{start:2,end:7}`; `locate('안되요 안되요','안되요',3)` deepEqual `{start:4,end:7}`; 없는 말 → `null`
  - `rectsFor([{item:0,start:0,end:4}], [{width:40}], 2, 4)` deepEqual `[{item:0,x0:20,x1:40}]`
  - `applyFixes('이걸 할수\n있다', [{start:3,end:8,fix:'할 수 있다'}])` === `'이걸 할 수 있다'`
  - `toPlainText([{text:'주민들은',right:100},{text:'모였다.',right:40},{text:'다음 문단',right:60}], 100)` === `'주민들은 모였다.\n다음 문단'`
  - `formatReport([{page:2,wrong:'덕하동카페',right:'',reason:'고유명사',unsure:true}])` 둘째 줄 === `'2\t덕하동카페\t(확인 필요)\t고유명사'`
- [ ] **Step 2:** `node --test landing/check/check-core.test.mjs` → FAIL (모듈 없음)
- [ ] **Step 3: 구현.** `dropLineBreakArtifacts`: `wrong`·`right`에서 공백을 다 지운 게 같고, `text`에 `wrong`이 그대로는 없지만 `text`에서 `"\n"`을 지운 문자열엔 있으면 버린다.

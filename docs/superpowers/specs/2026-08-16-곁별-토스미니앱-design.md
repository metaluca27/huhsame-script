# 곁별 토스 미니앱 (Phase 1) — 설계 문서

작성일: 2026-08-16

## 한 줄 소개

이미 웹으로 배포된 곁별(오행 정령 궁합 성좌지도)을 **앱인토스(토스) 미니앱**으로 올린다. 기능은 지금 그대로, 여기에 **내 정령 카드 이미지 공유**를 더해 자랑/유입 고리를 만든다.

## 범위

### 이번(Phase 1)
- 곁별 웹을 토스 미니앱으로 포팅 (기능 동일)
- 토스 웹뷰 맞춤 조정 (안전영역·뒤로가기·저장·경로)
- 정령 카드 이미지 공유 (토스 공유)
- 아이콘·브랜딩, 콘솔 등록·심사

### 범위 밖 (Phase 2 이후)
- 바이럴 공유(친구가 원격으로 내 지도에 생일 넣기) — 서버·DB 필요, 곁별의 완전 로컬 구조를 크게 바꿈. 별도 프로젝트.

## 참고: 검증된 패턴 (심연의 타로 미니앱)

`metaluca-fresh/miniapp-tarot/`가 동일 계열(사주·운세) 미니앱의 검증된 템플릿이다. 핵심:
- `granite.config.ts`: `appName`(콘솔 등록값과 일치, 수정 불가), `brand`(displayName·primaryColor·icon URL), `webViewProps.type: 'partner'`, `permissions: []`
- `package.json`: `@apps-in-toss/web-framework` + `vite`. scripts: `web:dev`(sync + vite), `web:build`(sync + vite build), `dev/build/deploy`(ait)
- `sync.mjs`: **루트 웹 원본의 파일들을 미니앱 `public/`으로 복사** + `index.html` 참조 경로 조정. 원본 한 벌만 유지, 미니앱은 자동 생성.
- 순수 클래식 스크립트(전역 변수 공유)라 번들링하지 않고 `public/`에 그대로 배포.

곁별은 타로와 달리 **서버 API(워커) 호출조차 없어** 더 단순하다.

## 1. 구조

새 폴더: `metaluca-fresh/miniapp-byeol/`

| 파일 | 역할 |
|---|---|
| `granite.config.ts` | appName `gyeotbyeol`, displayName `곁별`, primaryColor 성좌 남색, icon 호스팅 URL |
| `package.json` | web-framework + vite, 타로와 동일 scripts |
| `sync.mjs` | 곁별 웹 원본 → `public/` 복사 + index.html 경로 조정 |
| `index.html` | sync가 생성 (경로 조정본) |
| `public/` | sync가 채움 (곁별 파일들) |

원본 위치: `huhsame-script/landing/byeol/` **한 벌 유지**. 미니앱은 sync로 파생.

## 2. 웹 코드 재활용 (sync.mjs)

sync가 복사할 곁별 파일: `index.html`, `app.js`, `data.js`, `saju.js`, `compat.js`, `people.js`, `map.js`, `styles.css`, `lib/lunar.js`, `images/`(og.png 등).

- 곁별은 순수 로컬 계산(만세력·오행·궁합·지도 전부 클라이언트) → **복사만으로 거의 그대로 동작**.
- 스크립트 로드 순서(lunar → data → saju → compat → people → map → app) 유지.
- **경로 조정**: 곁별 index.html은 자산을 절대경로 `/byeol/...`로 참조 → 미니앱에선 `/...`(public 루트)로 치환. sync가 문자열 치환으로 처리(타로 sync 방식). 웹 원본은 `/byeol/` 유지(웹 배포는 그대로).

두 저장소 경로 처리: 미니앱 sync가 다른 저장소(huhsame-script)의 곁별을 참조해야 한다. 구현 시 확정할 옵션 — ⓐ sync가 huhsame-script 경로를 직접 참조(상대/절대), 또는 ⓑ 곁별 웹 원본을 metaluca-fresh로도 복제. **선호: ⓐ** (원본 한 벌 원칙 유지). 정확한 경로 방식은 구현 단계에서 확정.

## 3. 토스 웹뷰 맞춤 조정

- **안전영역**: `viewport-fit=cover` + `env(safe-area-inset-*)` 패딩으로 노치·토스 헤더 침범 방지.
- **뒤로가기**: 토스는 자체 뒤로가기(제스처/버튼)를 제공. 곁별은 SPA 화면 전환(`showScreen`)이라, 토스 뒤로가기가 곧장 앱을 닫지 않고 이전 화면으로 가도록 연동 필요(예: history 상태 사용 또는 web-framework 라우팅 훅). **실기기 확인 필요.**
- **localStorage**: 곁별 저장(`byeol_me`/`byeol_people`)이 토스 웹뷰에서 유지되는지 **실기기 확인 필요.** 안 되면 web-framework 저장 API로 대체.
- **자산 경로**: 위 2번 경로 치환.

## 4. 정령 카드 이미지 공유

내 정령 결과(내 정령 화면)에 "공유하기" 버튼을 추가.

- **카드 내용**: 정령 캐릭터(SVG) + 유형명("무르익은 빛돌") + 한 줄 소개 + "너는 어떤 정령?" + 곁별 로고.
- **이미지 생성**: 정령 카드를 캔버스 이미지로 렌더(SVG → canvas → PNG/dataURL). 곁별 정령은 SVG라 canvas에 그려 이미지화.
- **공유**: 토스 공유 기능으로 이미지 + 문구 전달. **토스 공유 SDK의 정확한 API(이미지 공유 지원 범위)는 구현 단계에서 확인.** 이미지 공유가 제한되면 폴백: 결과 문구 + 미니앱 링크 텍스트 공유.

## 5. 브랜딩 / 아이콘

- **아이콘**: 정령 얼굴(대표 정령) + 성좌 남색 배경. 토스 목록에서 눈에 띄게. 아이콘 이미지는 호스팅 URL로 등록(타로처럼).
- **displayName**: 곁별
- **primaryColor**: 성좌 남색 계열(예: `#1b2a5c`)
- 실제 아이콘 시안은 구현 단계에서 제작·확인.

## 6. 출시 플로 (앱인토스 워크플로 준수)

1. 콘솔(apps-in-toss 개발자센터)에서 앱 등록 — `appName: gyeotbyeol`(수정 불가 고유키)
2. `miniapp-byeol/` 구성 (granite.config·package·sync·아이콘)
3. `npm run build` → `.ait` 생성
4. `npm run deploy` — **배포 API 키는 루카가 직접 입력**(Claude는 키를 다루지 않음)
5. 출력되는 `intoss-private://gyeotbyeol?_deploymentId=...` → **https 다리 페이지**(예: `vaulted-bus-346411.web.app/byeol/test.html`)에 버튼으로 넣어 폰 테스트(카톡 클릭 우회)
6. 콘솔 상세설명 작성(무엇을 보고/누르고/경험하는지 구체적으로 — AI 심사) → [검토 요청하기] (심사 약 3영업일)

## 7. 구현 단계에서 확인·검증할 항목 (정직한 불확실성)

- 토스 웹뷰에서 localStorage 지속성
- 토스 뒤로가기 ↔ 곁별 화면 전환 연동
- 토스 공유 SDK의 이미지 공유 지원 범위 (안 되면 텍스트+링크 폴백)
- sync가 두 저장소(huhsame-script ↔ metaluca-fresh)를 참조하는 정확한 방식
- lunar.js(435KB)·rAF 애니메이션·CSS 표정 애니가 토스 웹뷰에서 정상 동작

## 8. 성공 기준

- 토스에서 곁별이 웹과 동일하게 동작(생일→정령→사람추가→성좌지도→순위→도감→표정)
- 내 정령 카드 이미지 공유가 동작(또는 폴백)
- 콘솔 심사 통과·출시

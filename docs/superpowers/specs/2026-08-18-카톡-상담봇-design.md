# 카카오톡 AI 상담봇 설계 (AI트렌드 다락방)

작성일: 2026-08-18
상태: **초안 — 루카 검토 대기**

---

## 1. 목표

루카의 카카오톡 채널 **AI트렌드 다락방**에 24시간 응대하는 AI 상담봇을 붙인다.

두 가지를 동시에 해결한다.

- **사업**: 랜딩페이지(`luca-darakbang.netlify.app/automation`)가 파는 "카카오톡 24시간 AI 상담봇"을 자기 채널에 먼저 적용한다. 채널 자체가 실물 데모가 되어 "저희 채널에 말 걸어보세요"가 가능해진다.
- **개인**: 같은 릴레이 위에 채널을 하나 더 붙이면 개인 비서용도 확장된다. 사업용이 개인용을 포함한다.

## 2. 오늘(2026-08-18) 확인된 사실

다음에 이어서 할 때 헛수고를 막기 위한 기록이다.

### 2-1. 공용 릴레이는 죽었다

`@bartlee_xx/kakao-talkchannel` 플러그인의 기본 릴레이 `https://k.tess.dev/`가 **DNS에서 사라졌다.**

- KT(168.126.63.1), 구글(8.8.8.8), 클라우드플레어(1.1.1.1) 세 곳 모두 `Non-existent domain`
- 상위 도메인 `tess.dev`는 살아 있음 → `k` 서브도메인만 내려감
- npm 최신 버전이 `0.5.1`로 설치본과 동일, 마지막 수정 2026-03-03 → 릴레이 주소를 고친 수정판 없음

**결론: "설치만 하면 공짜로 쓰는" 방식 1은 불가능하다.** 페어링 코드 발급 자체가 안 된다.
공용 채널(사만다, `pf.kakao.com/_scexbC`)에 말을 걸면 자동 인사말만 오고 답은 오지 않는다.
같은 증상을 다시 보면 이 항목을 먼저 의심할 것.

### 2-2. 오픈클로 게이트웨이가 3일간 반쯤 죽어 있었다

```
2026-08-15 21:52 · gateway.crash_loop_breaker
"3 unclean boot(s) within 300000ms; suppressing channel/provider account auto-start"
```

5분 안에 3번 죽어 안전장치가 걸렸고, **채널과 AI 프로바이더의 자동 시작이 억제된 상태**로 방치돼 있었다.
프로세스는 살아 있어 웹 UI는 200을 응답했기 때문에 겉으로는 정상으로 보였다.

- 조치: `openclaw gateway restart` → 정상 부팅, 새 크래시 번들 없음
- 설정 파일은 멀쩡했다 (`openclaw.json` 유효, `openclaw.json.last-good` 존재)
- 교훈: `openclaw status`의 빠른 조회는 겉만 본다. 실제 상태는 `openclaw channels status --channel <이름>`로 확인할 것.

### 2-3. 진단 명령 정리

| 목적 | 명령 |
|---|---|
| 전체 상태 (빠름, 부정확할 수 있음) | `openclaw status` |
| 채널 실제 구동 여부 | `openclaw channels status --channel kakao-talkchannel` |
| 채널 목록 | `openclaw channels list` |

| 실시간 로그 | `openclaw logs --follow` |

## 5. 설계 결정

### 5-1. `dmPolicy`를 `"open"`으로 바꾼다

현재 `"pairing"`이다. 이는 페어링을 마친 사람만 대화할 수 있다는 뜻인데, **고객은 페어링을 할 수 없다.**
이대로 두면 손님이 말을 걸어도 봇이 무시한다. 사업용 채널이므로 열어야 한다.

```json
{ "channels": { "kakao-talkchannel": { "accounts": { "default": {
  "enabled": true,
  "dmPolicy": "open",
  "relayUrl": "https://<루카 릴레이 주소>",
  "relayToken": "<발급 토큰>"
} } } } }
```

`relayToken`은 시크릿이므로 설정 파일에 평문으로 두지 않는다. 환경변수 또는 SecretRef를 쓴다.

### 5-2. 릴레이와 오픈클로를 같은 서버에 올린다

게이트웨이가 지금은 루카 PC에 있다. 그런데 파는 상품이 **"24시간 야간·주말 자동 응대"** 다.
PC를 끄면 새벽 문의를 놓치고, 그 약속을 못 지킨다.

→ 어차피 서버를 한 대 띄우는 김에 릴레이와 오픈클로를 함께 올린다. PC는 개발용으로 남긴다.

### 5-3. 상담봇 성격

- 랜딩페이지 FAQ를 근거로 답한다: 비용, 도입 기간, 기존 도구(카카오채널·시트·메일·결제) 연동, 유지보수
- 모르는 것을 지어내지 않는다. 확실하지 않으면 사람에게 넘긴다.
- 카톡 화면에 맞춰 짧게 답한다. 마크다운 기호를 쓰지 않는다(카톡에서 `**`가 그대로 보인다).

### 5-4. 사람에게 넘기기

봇이 못 푸는 문의는 상담톡으로 넘겨 루카가 직접 받는다. 견적·계약처럼 돈이 걸린 대화는 봇이 단정하지 않는다.

## 6. 남은 작업

1. nova 안의 스킬 등록 여부와 폴백 블록 연결 확인
2. 서버 확보 (오라클 무료 티어 / 라즈베리파이 / 시놀로지 / 기타)
3. Go 릴레이 서버 배포 → Admin UI에서 Account 생성 → `relayToken` 발급
4. 오픈클로 설정에 `relayUrl` · `relayToken` 반영, `dmPolicy`를 `open`으로
5. nova 스킬에 릴레이 주소 연결
6. 채널에 실제로 말을 걸어 응답 확인
7. (선택) 오픈클로 게이트웨이를 서버로 이전

---

## 7. 리스크

- **릴레이 저장소가 검증되지 않았다.** 별 0개, 마지막 커밋 2026-03-04. 막히면 물어볼 커뮤니티가 없다.
- **공용 릴레이가 이미 한 번 사라졌다.** 같은 저자의 프로젝트이므로 유지보수가 끊길 가능성을 감안한다. 자체 배포는 이 위험을 크게 줄인다.
- **오픈빌더 정책 변경 가능성.** 신청·승인 절차가 바뀌었는지 시작 시점에 확인한다.
- **PC 의존.** 5-2로 해소하지 않으면 "24시간"이 거짓말이 된다.

## 8. 범위 밖 (지금은 하지 않는다)

- 안드로이드 공기계 + 메신저봇R + 알뜰폰 유심 → **불필요해졌다.** 자체 채널과 챗봇이 이미 있다.
- 워커 `/kakao` 엔드포인트 신설 → 릴레이가 그 역할을 한다.
- 단톡방 봇, 이미지·음성 응대, 다국어
- 루남(공기계 mbot, 텔레그램) 무응답 문제 → 별개 시스템. 따로 다룬다. 배터리 최적화 해제부터 확인할 것.

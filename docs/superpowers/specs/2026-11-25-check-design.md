# 오탈자·띄어쓰기 검사기 (/check) — 짧은 설계

## 왜
루카가 부크크 종이책 원고와 지역신문 기사를 **최종 PDF 단계에서** 마지막으로 훑을 때 쓴다. 먼저 기사부터 쓰고, 책 원고는 그다음에 쓴다.

## 목표 / 하지 않을 것
- 목표: PDF를 올리면 **몇 쪽 · 틀린 부분 → 고친 부분 · 이유**가 표로 나온다. 오탈자와 띄어쓰기(맞춤법 포함)만 본다.
- 하지 않을 것: 문장 다듬기·윤문·문체 제안, PDF 직접 수정(고치는 건 루카가 원본에서 한다).
- 실패로 치는 것: PDF 줄바꿈 자국 때문에 생긴 **가짜 띄어쓰기 오류**가 쏟아지는 것, 멀쩡한 고유명사(지명·인명·가게 이름)를 오타로 잡는 것.

## 접근 (루카가 1번 선택)
1. **웹앱 /check + 공용 워커 제미나이** ← 선택. 어디서나 쓸 수 있고 기존 배포 방식 그대로.
2. 미니PC 전용 로컬 도구: 강의 나가 있을 때 못 씀.
3. 무료 맞춤법 검사기 연결: 비공식이라 자주 막히고 글자 수 제한이 있어 책 한 권엔 불안함.

## 화면 (루카가 정함: 둘 다)
- **왼쪽 = PDF 지면 + 빨간 줄**: 지면을 그대로 그리고 틀린 곳에 빨간 밑줄. 누르면 고칠 말이 뜬다. 빨간 줄 그은 PDF를 저장할 수 있다(책 원고는 이걸 보며 원본에서 고침).
- **오른쪽 = 글 + 고치기**: 뽑은 글에 같은 곳이 빨간 밑줄. 지적마다 [고치기] [무시], "확인 필요"는 직접 고쳐 쓰기 칸. [고친 글 전체 복사]로 기사 송고란에 바로 붙인다.
- 왼쪽·오른쪽 같은 지적은 서로 연결(한쪽을 누르면 다른 쪽도 표시).

## 어떻게 (클로가 정한 것)
- 화면: `landing/check/` 한 페이지. PDF 끌어다 놓기 → 원고 종류 고르기(**신문기사** 기본 / 책 원고) → 검사 → 위 두 칸. 지적 목록 복사 버튼도 둔다.
- 고친 글 복사 때 줄 이어 붙이기: 오른쪽 끝까지 찬 줄은 문단 안 줄바꿈으로 보고 한 칸 띄워 잇고, 짧게 끝난 줄은 문단 끝으로 본다. 단어 중간에서 줄이 바뀐 PDF는 엉뚱한 띄어쓰기가 생길 수 있음 — 실제 기사 PDF로 확인해서 조정.
- PDF 글자 뽑기: 브라우저 안에서 pdf.js로 쪽마다 뽑는다(파일 자체는 어디에도 올리지 않음). 줄 끝 글자 위치를 보고 줄바꿈 자국을 이어 붙인 뒤, 제미나이에게도 "줄바꿈 자리 띄어쓰기는 판단하지 말 것"을 알린다.
- 워커: 새 경로 `POST /check`. 몇 쪽씩 묶어(약 3,000자) 보내고 JSON 목록으로 받는다. 책처럼 긴 원고는 묶음 단위로 차례로 돌리며 진행률 표시.
- 기준: 기사 모드는 표준 맞춤법·띄어쓰기를 깐깐하게. 책 모드는 따옴표 안 대사의 구어체·의도한 말투는 넘어간다. 두 모드 모두 확신 없는 고유명사는 "확인 필요"로만 표시.
- 배포: Firebase `vaulted-bus-346411` 의 `/check`, 워커는 `wrangler deploy`.

## 빌더에게 맡기는 것
화면 꾸밈, 묶음 크기 세부, 결과 표에서 PDF 원문 문장 앞뒤를 얼마나 보여줄지.

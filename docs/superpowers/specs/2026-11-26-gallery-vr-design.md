# 모닥불 전시장(/gallery) VR 모드 — 짧은 설계

## 왜
루카가 XR(헤드셋 속 3D 체험) 영상을 보고 직접 해보고 싶어 함. 헤드셋은 아직 없으니
에뮬레이터(가상 헤드셋)로 먼저 만들어 보고, 새로 만드는 대신 이미 있는 3D 전시장에 붙인다.

## 목표 / 하지 않을 것
- 목표: /gallery 에 "VR로 입장" 버튼 → 헤드셋(또는 에뮬레이터) 안에서 모닥불 전시장을 둘러보기.
- 하지 않음: 기존 폰·PC 화면 동작 변경, /sarang 적용(이건 다음 단계), 조이스틱 걷기.
- 실패로 치는 것: 기존 화면이 조금이라도 깨지는 것, VR 안에서 멀미 나는 자동 카메라 이동.

## 이동 방식 (루카 선택: B)
| 안 | 내용 | 결과 |
|---|---|---|
| A | 불가에 서서 고개만 돌리기 | 그림이 멀어서 작게 보임 |
| **B** | **가리키고 누르면 순간이동** | **선택** — 퀘스트 앱 표준, 멀미 없음 |
| C | 조이스틱 걷기 | 초보자 멀미 |

## 동작
- 시작 자리: 모닥불 옆, 첫 그림을 바라보는 방향.
- 컨트롤러(또는 손 집기)로 **그림**을 가리키고 누르면 → 그 그림 정면 약 2m 앞으로 이동, 그림을 바라보게 돌려줌.
- **땅**을 가리키고 누르면 → 그 자리로 이동(모닥불 안·전시장 밖으로는 못 감). 가리키는 곳에 동그란 표시.
- 그림마다 아래쪽에 **3D 명패**(번호·제목·연도·설명). VR 중에만 보이고 평소 화면에선 숨김.
- 배경음악은 VR 입장 때도 재생.
- VR 버튼은 브라우저가 VR을 지원할 때만 보임(입장 화면 + 위쪽 도구 줄).

## 만드는 방법 (클로 판단)
- three.js 내장 WebXR 기능 사용. 카메라를 "몸통" 그룹 안에 넣고, 순간이동은 몸통을 옮기는 방식.
- 화면 갱신을 VR 호환 방식(setAnimationLoop)으로 바꾸되, 평소 모드의 카메라 연출은 그대로.
- 확인용으로 `?xr=emu` 를 붙이면 Meta의 웹 에뮬레이터 라이브러리(IWER)를 불러와 가상 헤드셋을 켬.
  루카는 크롬 확장 "Immersive Web Emulator"로도 볼 수 있음.

## 확인과 반영
- 로컬에서 띄워 에뮬레이터로: 입장 → 그림 가리켜 이동 → 땅 이동 → 명패 보임 → 나가면 원래 화면 그대로.
- 실제 사이트 배포는 루카 확인 후 따로.

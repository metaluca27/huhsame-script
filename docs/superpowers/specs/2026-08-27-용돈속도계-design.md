# 용돈 속도계 — 앱인토스 미니앱 설계

작성 2026-08-27

## 왜 만드나

앱인토스에 '재테크' 카테고리가 새로 생겼는데(2026년 8월 5주 업데이트) 우리 앱 14개
중 거기 들어갈 것이 하나도 없다. 토스가 새 탭을 밀어주는 시기라 자리가 비어 있다.

목표는 **인앱 광고 수익**이다. 2026-08-28부터 사업자 등록 없이도 광고 ID를 받을 수
있게 됐다(누적 예상수익 5천원까지 유예).

기존 14개는 대부분 한 번 쓰고 마는 계산기다. 광고로 돈이 되려면 **다시 오게 만드는
앱**이 필요하다. 이 앱은 매일 아침 한 번씩 열어보는 습관을 노린다.

## 토스 본체와 겹치지 않는 지점

토스 앱에는 이미 가계부와 소비 분석이 있다. 정면으로 겹치면 손님이 미니앱을 쓸 이유가
없다.

- 토스 가계부 = **쓴 돈을 기록**한다 (과거)
- 용돈 속도계 = **남은 돈의 속도**를 본다 (지금 페이스와 앞으로)

## AI를 쓰지 않는다

광고 수익이 목표인데 AI를 부르면 사람이 많이 올수록 비용이 커진다. 호출 한 번에
몇 원~몇십 원인데 미니앱 광고 노출 단가도 그 정도라, 잘될수록 손해 보는 구조가 된다.
이 앱은 계산만으로 동작하므로 호출 비용이 0원이다.

## 화면 흐름

### 처음 열었을 때

질문 하나만 던진다. 설정 화면은 만들지 않는다.

> 이번 달 쓸 수 있는 돈이 얼마예요?
> `[ 500,000 ]` → 시작하기

### 그 다음부터

열면 바로 이 화면이다.

```
        지금 남아 있어야 할 돈
            258,000원

     실제 남은 돈    230,000원
     ───────────────────────
     28,000원 앞서가는 중 🏃

     이 페이스면 27일에 바닥나요

   [ 남은 돈 고치기 ]  [ 쓴 돈 기록 ]
```

**두 숫자는 반드시 같은 단위여야 한다.** 둘 다 "잔액"이다. 하나를 누적 지출로 잡고
다른 하나를 잔액으로 잡아 빼면 의미 없는 숫자가 나온다.

상태에 따라 문구가 바뀐다.

| 상태 | 문구 예시 |
|---|---|
| 기준보다 적게 남음(많이 씀) | 28,000원 앞서가는 중 🏃 |
| 기준보다 많이 남음 | 48,000원 여유 있어요 🌿 |
| 차이가 예산의 2% 안쪽 | 딱 맞게 가고 있어요 👌 |
| 남은 돈이 0 이하 | 이번 달 예산을 32,000원 넘었어요 |

## 계산

모든 비교는 **잔액 기준**으로 한다.

```
전체 날    = 이번 달 총 일수
지난 날    = 오늘 날짜 (1일이면 1)
남은 날    = 전체 날 − 지난 날

기준 잔액  = 예산 × (남은 날 ÷ 전체 날)      지금쯤 남아 있어야 할 돈
쓴 돈      = 예산 − 남은 돈
차이       = 기준 잔액 − 남은 돈             양수면 앞서가는 중(더 썼다)
하루 평균  = 쓴 돈 ÷ 지난 날
바닥 예상  = 오늘 + (남은 돈 ÷ 하루 평균) 일
```

예: 예산 500,000원, 8월 15일(31일 중 15일 지남, 16일 남음), 남은 돈 230,000원

| 항목 | 계산 | 값 |
|---|---|---|
| 기준 잔액 | 500,000 × 16/31 | 258,064 → **258,000원** (백원 단위 내림) |
| 쓴 돈 | 500,000 − 230,000 | 270,000원 |
| 차이 | 258,064 − 230,000 | **+28,064** → 앞서가는 중 |
| 하루 평균 | 270,000 ÷ 15 | 18,000원 |
| 바닥 예상 | 230,000 ÷ 18,000 = 12.8일 | 8월 15일 + 12일 = **8월 27일** |

기간은 **매월 1일 시작 고정**이다. 월급날 기준으로 잡으면 현실에 더 맞지만 설정이
하나 늘어난다. 첫 화면에 아무 설정도 없는 편이 낫다고 판단했다.

## 입력 두 가지가 같은 값을 갱신한다

진짜 상태는 **남은 돈** 하나뿐이다.

- **남은 돈 고치기** — 토스 잔액을 보고 숫자 하나를 친다. 이것이 기본 경로다.
- **쓴 돈 기록** — "9,000"을 넣으면 남은 돈에서 자동으로 빠진다.

이렇게 묶으면 기능이 둘이어도 화면이 늘지 않는다. 며칠 기록을 빼먹어도 잔액만 다시
맞추면 복구된다 — 매일 입력을 강요하는 가계부가 사흘 만에 버려지는 이유를 피한다.

## 저장

**localStorage에만 저장한다. 서버를 쓰지 않는다.**

- 돈 이야기인데 아무 데도 보내지 않으므로 개인정보 문제가 없고 검수가 수월하다
- 서버 비용 0원
- 화면에 "이 기록은 서버로 보내지 않고 내 폰에만 저장돼요 🔒"를 표시한다
  (축의금 계산기와 같은 방식)

한계: 폰을 바꾸거나 토스 앱 데이터를 지우면 사라진다. 몇 년치를 쌓는 가계부가 아니라
이번 달만 보는 앱이므로 감당할 만하다.

저장 항목:

```
budget       이번 달 예산
remaining    남은 돈
month        기준 연월 (예: "2026-08")
lastBudget   지난달 예산 (다음 달 제안용)
lastResult   지난달 마감 결과 (남긴 금액 또는 초과 금액)
```

## 예외 상황

**월이 바뀌면** — 저장된 `month`가 이번 달과 다르면 새 달을 시작한다.

> 9월이 시작됐어요.
> 지난달은 **12,000원 남기고** 끝냈어요 👏
> 이번 달도 500,000원으로 갈까요? `[네]` `[바꿀래요]`

지난달 결과를 한 줄 보여주는 것이 핵심이다. **월초에 다시 오게 만드는 장치**다.

**예산을 넘으면** — 자책하게 만들면 앱을 지운다. 톤을 바꿔 남은 날을 기준으로 말한다.

> 이번 달 예산을 **32,000원** 넘었어요
> 남은 3일이에요. 여기서 멈추면 32,000원 초과로 마감돼요

새 예산을 제시하지 않는다. 이미 넘긴 사람에게 "하루 얼마씩 쓰세요"라고 하면 앞뒤가
맞지 않는다. 사실만 담담히 보여주고 판단은 사용자에게 맡긴다.

**첫날이거나 아직 안 썼으면** — 하루 평균이 0이라 "바닥 예상"이 계산되지 않는다.
그 줄을 숨기고 대신 이렇게 보여준다.

> 이번 달 하루 16,129원씩 쓸 수 있어요

**입력값 방어** — 음수, 0, 예산보다 큰 남은 돈, 숫자가 아닌 값을 막는다.

## 광고 배치

**메인 화면 맨 아래 배너 하나.** 매일 열리는 화면이라 그 한 자리가 반복 노출된다.
중간에 끼우거나 전면 광고를 띄우면 매일 쓰는 앱에서는 금방 질려 이탈을 부른다.

## 만들지 않을 것

- 카테고리별 분류(식비·교통비 등) — 토스 가계부 영역이다
- 그래프·통계
- 여러 달 비교
- 카드·계좌 연동 — 미니앱에서는 불가능하다
- 알림·푸시

## 기술

기존 미니앱과 같은 패턴을 따른다([[apps-in-toss-workflow]] 참고).

- `metaluca8560/metaluca8560` 저장소의 `miniapp-<이름>/` 폴더
- `@apps-in-toss/web-framework` 3.1.1 + vite (`apps-in-toss.config.ts`)
- 루트에 원본 HTML 한 벌을 두고 `sync.mjs`로 미니앱용 `index.html` 생성
- 외부 API 호출이 없으므로 CORS 설정이 필요 없다

appName은 콘솔에서 앱을 만들 때 정해지며 수정할 수 없다. 후보: `yongdon-speed`.

## 열린 질문

- 콘솔 카테고리를 '재테크'로 지정할 수 있는지 확인 필요 (신설된 탭)
- 인앱 광고 SDK 연동 방법은 광고 ID 발급 후 확인한다

# 구독료 다이어트 — 앱인토스 미니앱 설계

작성 2026-08-27

## 왜 만드나

[용돈 속도계](2026-08-27-용돈속도계-design.md)와 함께 앱인토스 '재테크' 카테고리를
노리는 두 번째 미니앱이다. 목표는 인앱 광고 수익.

두 앱은 역할이 다르다.

| 앱 | 역할 | 재방문 |
|---|---|---|
| 용돈 속도계 | 다시 오게 한다 | 매일 |
| 구독료 다이어트 | 새로 들어오게 한다 | 낮음 (공유로 유입) |

숫자 충격이 커서 공유가 잘 되는 소재다. 월 15만원은 그러려니 넘기지만 "연 187만원"은
넘기지 못한다. 그 한 줄이 이 앱의 전부다.

## AI를 쓰지 않는다

계산과 목록만으로 동작한다. 광고 수익이 목표인데 AI 호출 비용이 광고 노출 단가와
비슷해서, 사용자가 늘수록 손해 보는 구조가 되기 때문이다. 용돈 속도계와 같은 판단이다.

## 화면 1 — 고르기

> **쓰고 있는 구독을 골라주세요**

자주 쓰는 서비스 30개쯤을 묶어서 보여준다. 탭 한 번에 체크되고 대표 가격이 자동으로
들어간다.

```
영상       넷플릭스  티빙  웨이브  디즈니+  쿠팡플레이  왓챠  유튜브프리미엄
음악       스포티파이  유튜브뮤직  멜론  지니  플로
AI         챗GPT  클로드  퍼플렉시티  코파일럿
쇼핑·배송   쿠팡와우  네이버플러스  배민클럽
생산성     노션  어도비  MS365  구글원  드롭박스
                                                [ + 직접 추가 ]
```

체크하면 아래에 금액이 붙는다. **숫자를 누르면 그 자리에서 고칠 수 있다.**

### 가격이 틀려지는 문제

미리 넣어둔 가격은 시간이 지나면 반드시 틀려진다. 요금은 자주 오르고, 같은 서비스도
요금제가 여러 개다. 충격 숫자가 틀리면 앱의 신뢰가 통째로 무너진다. 미니앱은 고칠
때마다 심사를 거쳐야 해서 즉시 반영도 안 된다.

세 가지로 막는다.

1. 금액을 사용자가 그 자리에서 고칠 수 있게 한다 (가장 중요)
2. 가격 옆에 "2026년 8월 기준"을 작게 표시해 대략치임을 밝힌다
3. 요금제가 여러 개인 서비스는 **가장 흔한 요금제 하나**만 넣는다. 요금제를 고르게
   하면 30초 안에 안 끝난다

가격 목록은 코드 안의 상수 하나로 모아 둔다. 갱신할 때 한 곳만 고치면 되도록.

## 화면 2 — 충격

```
        쓰고 계신 구독 12개

           한 달 155,800원
           1년이면
        1,869,600원 💸

        하루로 치면 5,122원
        커피로 치면 374잔

     ───────────────────────
     제일 비싼 것
     1. 챗GPT        29,000원
     2. 어도비        24,000원
     3. 쿠팡와우       7,890원
```

계산은 단순하다.

```
월 합계   = 고른 구독 금액의 합
연 합계   = 월 합계 × 12
하루      = 연 합계 ÷ 365
커피 잔수 = 연 합계 ÷ 5,000
```

예시 검산: 155,800 × 12 = 1,869,600 / 1,869,600 ÷ 365 = 5,122 /
1,869,600 ÷ 5,000 = 374잔.

환산 비유는 **커피와 하루치 두 개만** 쓴다. "제주도 항공권 몇 번" 같은 비유는 그 값도
시간이 지나면 틀려져서 유지보수 대상이 하나 더 늘어난다.

## 화면 3 — 다이어트

여기서 앱 이름값을 한다.

> **3개월 넘게 안 쓴 게 있나요?**
> (고른 것 중에서 다시 체크)

```
     이것만 정리하면

       1년에 577,200원 아껴요

     · 왓챠       7,900원
     · 어도비    24,000원
     · 드롭박스  16,200원
```

검산: (7,900 + 24,000 + 16,200) × 12 = 48,100 × 12 = 577,200.

앱이 "안 쓰는 것"을 알아낼 방법은 없다. 사용자가 직접 체크한다. 이미 고른 목록에
체크를 한 번 더 하는 것뿐이라 만드는 비용이 거의 없다.

**실제 해지는 각 서비스에서 해야 한다.** 미니앱이 대신 해줄 수 없고, 앱인토스는 미니앱
밖으로 나가는 링크를 금지하므로 해지 페이지 링크도 넣지 않는다. "무엇을 끊어야 하는지
정해주는 것"까지가 이 앱의 몫이다.

## 공유

이 앱의 유입은 공유에서 나온다.

토스 SDK의 공유 기능을 쓴다(`window.AppsInToss.share`, 기존 미니앱에서 동작 확인됨).
문구는 숫자를 앞세운다.

> 저는 구독료로 1년에 1,869,600원 쓰고 있었어요 😱

곁별에서 만든 canvas 공유 카드 방식([[byeol-app]])을 나중에 붙일 수 있지만, 1차
범위에는 넣지 않는다. 텍스트 공유만으로 충분히 돈다.

## 저장

**localStorage에만 저장한다. 서버를 쓰지 않는다.**

다시 열면 지난번에 고른 목록과 수정한 금액이 그대로 남아 있다. 매번 12개를 다시 고르게
하면 두 번째 방문이 사라진다.

저장 항목:

```
selected    고른 서비스 id 목록
prices      사용자가 고친 금액 (서비스 id → 금액)
custom      직접 추가한 항목 (이름 + 금액)
unused      "안 쓴다"고 체크한 id 목록
```

서버를 안 쓰므로 개인정보 문제가 없고 검수가 수월하다. 화면에 "이 기록은 서버로 보내지
않고 내 폰에만 저장돼요 🔒"를 표시한다.

## 예외 상황

| 상황 | 처리 |
|---|---|
| 아무것도 안 골랐을 때 | 결과 화면으로 못 넘어가게 하고 "하나만 골라도 돼요" 안내 |
| 금액을 0으로 고쳤을 때 | 허용한다. 무료 요금제를 쓰는 사람이 있다 |
| 직접 추가에 이름만 넣었을 때 | 금액을 0으로 두지 말고 입력을 요구한다 |
| 안 쓰는 것을 하나도 안 골랐을 때 | "정리할 게 없네요 👏"로 마무리. 빈 화면을 보여주지 않는다 |
| 숫자가 아닌 값·음수 | 막는다 |

## 광고 배치

**결과 화면(화면 2) 아래 배너 하나.** 충격 숫자를 본 직후가 화면에 가장 오래 머무는
지점이다. 고르는 화면(화면 1)에는 넣지 않는다 — 체크 흐름을 끊으면 완주율이 떨어진다.

## 만들지 않을 것

- 결제일 입력과 "3일 뒤 결제" 알림 — 입력 부담이 커서 중간에 포기한다. 재방문은
  용돈 속도계가 맡는다
- 해지 페이지 연결 — 미니앱 밖 링크 금지
- 카드·계좌 연동 — 미니앱에서는 불가능
- 요금제 선택 (스탠다드/프리미엄 등) — 30초 안에 안 끝난다
- 여러 사람 비교·평균 통계 — 서버가 필요하다

## 기술

기존 미니앱과 같은 패턴을 따른다([[apps-in-toss-workflow]] 참고).

- `metaluca8560/metaluca8560` 저장소의 `miniapp-<이름>/` 폴더
- `@apps-in-toss/web-framework` 3.1.1 + vite (`apps-in-toss.config.ts`)
- 루트에 원본 HTML 한 벌을 두고 `sync.mjs`로 미니앱용 `index.html` 생성
- 외부 API 호출이 없으므로 CORS 설정이 필요 없다

appName은 콘솔에서 앱을 만들 때 정해지며 수정할 수 없다. 후보: `subscription-diet`.

## 열린 질문

- 콘솔 카테고리를 '재테크'로 지정할 수 있는지 확인 필요 (신설된 탭)
- 서비스 30개의 목록과 2026년 8월 기준 가격은 구현 단계에서 조사해 채운다
- 인앱 광고 SDK 연동 방법은 광고 ID 발급 후 확인한다

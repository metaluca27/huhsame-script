# 다락방 식구들 상황판 설계

날짜: 2026-11-12

## 목적

다락방 식구 7명(푸름이, 루릭, 주주야, 노바, 헤르미, 루나, 클로)이 지금 무엇을 하고 있는지 한 화면에서 본다. 꾸민 숫자가 아니라 식구들이 실제로 남긴 기록을 읽어서 보여준다.

계기는 X에서 본 "봇 팀 대시보드" 홍보 영상이다. 그 영상은 연출된 모션그래픽이었고, 이 상황판은 같은 모양을 실제 기록으로 만든다.

## 범위

넣는 것:

- 미니PC에서만 열리는 한 장짜리 화면
- 식구별 상태, 마지막 활동 시각, 오늘 건수, 최근 한 일 한 줄
- 전체 숫자 띠와 시간순 활동 일지
- 전원 무소식 경고

넣지 않는 것:

- 상황판에서 식구에게 일을 시키는 기능
- 폰에서 보기, 외부 공개 배포
- 식구 캐릭터 그림 (1차는 이름과 색으로 구분)
- AI 호출 (요약, 말투 입히기 등)

## 구조

두 부분으로 나눈다. 둘은 요약 파일 한 장으로만 이어진다.

```
식구들 기록 파일 ──(읽기 전용)──> 수집기 ──> status.json ──> 화면
```

위치: `tools/attic-family/`

| 파일 | 하는 일 |
|---|---|
| `collect.py` | 1분마다 기록을 읽어 `status.json`을 새로 쓴다 |
| `index.html` | `status.json`을 30초마다 다시 읽어 화면을 그린다 |
| `상황판_열기.bat` | 수집기와 로컬 서버를 켜고 브라우저로 연다 |
| `status.json` | 수집 결과. git에 올리지 않는다 |

로컬 서버는 `127.0.0.1`에만 묶는다. 포트는 8793 (8765는 agentcat, 8787은 AI 사무실, 8792는 손 홀로그램이 쓴다).

## 수집기

식구마다 읽는 곳이 다르다. 식구 한 명당 함수 하나로 나누고, 모두 같은 모양의 결과를 돌려준다.

| 식구 | 읽는 곳 | 읽는 값 |
|---|---|---|
| 푸름이 | `~/.openclaw/agents/main/agent/openclaw-agent.sqlite` | `session_nodes`의 마지막 활동 시각과 대화 이름, `transcript_events`의 오늘 건수 |
| 루릭 | 같은 구조, `agents/lurick` | 같음 |
| 주주야 | 같은 구조, `agents/jujuya` | 같음 |
| 노바 | 같은 구조, `agents/nova` + 헤르메스의 "노바"로 시작하는 예약 작업 2개 | 오픈클로 쪽은 시각과 건수만(대화 이름과 내용은 읽지 않는다). 헤르메스 쪽은 마지막 실행 시각과 결과. 카드 한 장에 두 줄로 보여준다 |
| 헤르미 | `~/AppData/Local/hermes/cron/jobs.json`, `cron/executions.db` | 이름이 "헤르미"로 시작하는 예약 작업의 마지막 실행 시각, 결과, 다음 실행 시각 |
| 루나 | 같은 파일 | 이름이 "루나"로 시작하는 예약 작업 |
| 클로 | 이 저장소의 `git log` | 오늘 커밋 수, 마지막 커밋 시각과 제목 |

헤르메스 예약 작업은 2026-11-12 기준 7개다: 루나 4개, 노바 2개, 헤르미 1개. 이름 앞머리로 식구를 가른다. 어느 식구에도 안 맞는 이름의 작업이 생기면 버리지 않고 헤르미 카드에 넣는다 (헤르메스의 주인이 헤르미이므로).

식구별 결과 모양:

```json
{
  "id": "pureum",
  "name": "푸름이",
  "state": "active | quiet | error | unreadable",
  "last_at": "2026-11-12T19:20:00+09:00",
  "today_count": 12,
  "last_line": "최근 한 일 한 줄",
  "detail": "오류나 못 읽은 이유 (있을 때만)"
}
```

상태 기준:

- `active`: 오늘 활동이 한 건 이상
- `quiet`: 오늘 활동 없음
- `error`: 헤르메스 예약 작업의 마지막 결과가 실패이거나 닫히지 않은 사고 기록이 있음
- `unreadable`: 기록 파일을 열지 못함

`status.json` 전체에는 식구 목록, 수집 시각, 합계(오늘 총 건수, 활동 중인 식구 수, 오류 수), 최근 활동 일지 30줄, 경고 목록이 들어간다.

## 화면

- 가운데에 루카. 식구 카드 7장이 둘러싸고 선으로 이어진다.
- 최근 10분 안에 활동한 식구의 선은 반짝인다.
- 카드: 이름, 상태 불(초록·회색·빨강·"기록 못 읽음"), 마지막 활동 시각, 오늘 건수, 최근 한 일 한 줄.
- 위쪽 숫자 띠: 오늘 총 건수, 활동 중인 식구 수, 오류 수.
- 아래쪽 일지: 식구 전체의 최근 활동을 시간순으로 한 줄씩.
- 화면 구석에 "몇 시 몇 분 기준"을 항상 표시한다. 수집이 3분 넘게 멈추면 "수집이 멈췄어요"를 띄운다.

## 안전장치

- 모든 기록 파일은 읽기 전용으로 연다 (`sqlite3`의 `mode=ro`). 식구들의 설정이나 기록을 바꾸지 않는다.
- 비밀키가 들어 있는 파일(`config.yaml`, `auth.json`, 인증 관련 표)은 열지 않는다.
- 노바(카톡 상담)는 손님 개인정보가 있으므로 건수와 시각만 내보낸다.
- 못 읽은 값은 0이나 추측으로 채우지 않고 `unreadable`로 표시한다.
- 오픈클로 식구 4명이 모두 24시간 넘게 조용하면 "게이트웨이가 멈췄을 수 있어요" 경고를 띄운다. 2026년 8월에 게이트웨이가 겉보기엔 멀쩡한 채 3일간 멈춘 일이 있었다.

## 확인 방법

- 수집기의 식구별 함수는 작은 가짜 기록 파일을 만들어 테스트한다 (정상, 빈 파일, 파일 없음).
- 완성 후 실제로 띄워서, 화면의 식구별 건수와 시각을 기록 파일을 직접 조회한 값과 대조한다.
- 기록 파일 하나를 일부러 못 읽게 한 상태에서 "기록 못 읽음"이 뜨는지 확인한다.

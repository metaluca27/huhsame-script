# 마주톡 — 여행 실시간 음성 대화 번역기 설계서

날짜: 2026-07-10
상태: 사용자 승인 대기

## 한 줄 요약

여행지에서 폰을 사이에 두고 현지인과 마주보며 대화하는 음성 번역 웹앱.
내가 한국어로 말하면 상대 언어로, 상대가 자기 언어로 말하면 무조건 한국어로
번역해서 보여주고 소리로 읽어준다.

## 목표

- 한국어 ↔ 일본어 / 영어 / 스페인어 / 이집트 아랍어 양방향 음성 대화 번역
- 상대방 말은 항상 한국어로 번역 (여행자 본인 기준)
- 마주보기 분할 화면: 상대방 영역은 글자가 180도 뒤집혀 상대 쪽에서 바로 보임
- 번역 결과 자동 음성 재생 (TTS)
- 주 사용 환경: 안드로이드 크롬

| 항목 | 결정 |

## 전체 구조

```
폰 브라우저 (landing/talk/index.html)
   → 마이크 버튼 → SpeechRecognition (내 버튼 ko-KR / 상대 버튼 선택 언어)
   → 말하는 중 중간 인식 결과 실시간 표시
   → 인식 완료 → POST /translate  { text, from, to }
      → Gemini Flash 번역  ※ 실패 시 Claude 폴백
   ← { translation }  JSON
   → 화면 표시 + SpeechSynthesis 자동 재생
```

## 화면 구성 (마주보기 분할)

세로 화면을 위아래 반으로 나눈다.

**위쪽 절반 = 상대방 영역** (`transform: rotate(180deg)` — 상대 쪽에서 정방향으로 보임)

- 언어 선택 버튼 4개: 🇯🇵 日本語 / 🇺🇸 English / 🇪🇸 Español / 🇪🇬 العربية
  (버튼 라벨은 해당 언어 원어 표기 — 상대방이 읽는 버튼이므로)
- 상대방용 마이크 버튼. 상대방이 누르고 자기 언어로 말한다.
- 내가 말한 문장의 번역이 이 영역에 크게 표시 + 상대 언어로 음성 재생
- 마이크 버튼 안내 문구도 선택된 언어로 표기 (예: "Tap and speak")

**아래쪽 절반 = 내 영역** (정방향, 한국어 UI)

- 내 마이크 버튼. 내가 누르고 한국어로 말한다.
- 상대방이 말한 문장의 한국어 번역이 여기 크게 표시 + 한국어 음성 재생
- 말하는 동안 중간 인식 결과가 실시간으로 보임 (회색 → 확정 시 검정)

**가운데 경계선**

- 대화 기록 버튼: 최근 30건 (원문·번역·방향·시각) localStorage 저장, 목록 보기·전체 삭제
- 음성 자동재생 켜기/끄기 토글 (조용한 곳 대비)

## 동작 흐름

1. 마이크 버튼 누름 → SpeechRecognition 시작
   - 내 버튼: `lang = ko-KR`, 상대 버튼: 선택 언어 (`ja-JP` / `en-US` / `es-ES` / `ar-EG`)
   - `interimResults: true`로 중간 결과 실시간 표시
2. 인식 종료(무음 감지 또는 버튼 재탭) → 확정 텍스트를 워커로 전송
3. 워커가 Gemini로 번역. 이집트 아랍어로 번역할 때는 프롬프트에서
   **이집트 구어체(마스리, العامية المصرية)** 를 명시 — 문어체(푸스하) 금지
4. 번역 결과 표시 + 자동 TTS
   - TTS 보이스 선택: `speechSynthesis.getVoices()`에서 대상 언어 일치 보이스 탐색
   - 이집트 아랍어: `ar-EG` 보이스 없으면 `ar-*` 아무 보이스로 대체,
     그것도 없으면 음성 생략하고 글자만 표시 (에러 표시하지 않음)
5. 대화 기록에 저장

## 워커 API 명세

`POST /translate`

요청:
```json
{ "text": "화장실이 어디예요?", "from": "ko", "to": "ar-EG" }
```

응답:
```json
{ "translation": "فين الحمام؟" }
```

- 언어 코드: `ko`, `ja`, `en`, `es`, `ar-EG` (이집트 방언 구분 위해 ar-EG 유지)
- Gemini Flash 호출 실패(키 없음·에러·타임아웃) 시 Claude 폴백 — `/scan`과 동일 구조
- 번역 프롬프트: 여행 회화 맥락, 자연스러운 구어체, 번역문만 출력 (설명 금지)
- CORS: 기존 워커 공통 헤더 그대로

## 에러 처리

- 마이크 권한 거부 → 안내 메시지 + 텍스트 입력창 폴백 (타이핑으로도 번역 가능)
- 음성인식 무음/실패 (`no-speech`, `audio-capture`) → "잘 못 들었어요, 다시 말해주세요"
  (상대 영역이면 해당 언어로 표시)
- 워커 응답 실패 → 마지막 원문 유지 + 재시도 버튼
- 오프라인 → 상단 배너 "인터넷 연결이 필요해요" (`navigator.onLine` + fetch 실패 감지)
- Web Speech 미지원 브라우저 → 텍스트 입력 모드로 자동 전환

## 테스트

- 데스크톱 크롬에서 5개 언어 방향별 번역·TTS 수동 확인 (음성인식은 데스크톱 크롬도 지원)
- 이집트 아랍어 번역이 구어체로 나오는지 샘플 문장으로 확인
  (예: "화장실이 어디예요?" → "فين الحمام؟"가 나와야 함. 푸스하 "أين الحمام؟"면 프롬프트 수정)
- 워커 `/translate` curl 테스트 (배포 후)
- 실기기(안드로이드 폰)에서 마이크 → 번역 → TTS 전체 흐름 확인은 사용자가 진행

# 리버스 비즈니스 해부기 (토스 미니앱 17호) — 설계

작성 2026-11-26 · 루카와 브레인스토밍으로 정함 · 앱 이름은 가제

## 1. 왜 만드나

- 출발점: 커넥트 AI 랩 「THE FOUNDER EP.3」 영상. 메시지는 "만들 줄 아는 것과 돈 버는 건 다르다". 잘 되는 서비스를 볼 때 코드가 아니라 **누가 사는지, 얼마를 받는지, 어떤 흐름으로 파는지**를 뜯어보라는 것.
- 영상 속 도구(`reversebusiness`, 오픈소스)는 개발 도구 안에서만 돌아간다. 이걸 **토스 안에서 주소 하나 넣으면 되는 앱**으로 만들어, 개발을 모르는 사람도 쓰게 한다.
- 루카에게는 재테크·부업 쪽 앱 라인(용돈 속도계, 구독료 점검)을 넓히는 일이기도 하다.

## 2. 누구를 위한 앱인가

부업을 찾는 사람, 창업을 준비하는 사람, 1인 CEO. 루카가 정함.

이 사람들이 앱에서 얻어 가야 할 것: **"잘 되는 저 서비스는 이렇게 돈을 버는구나"를 이해하고, "나라면 이렇게 바꿔 보겠다"는 힌트 3줄.**

## 3. 목표 / 목표 아님 / 실패로 치는 것

**목표**
- 주소 하나를 넣으면 1분 안에 해부 리포트가 나온다.
- 리포트의 모든 내용이 **관찰(페이지에서 직접 봄) / 추정(근거를 들어 짐작) / 모름**으로 구분된다.
- 처음 온 사람도 추천 사이트를 눌러 바로 리포트를 볼 수 있다(기다림 0초, AI 비용 0원).

**목표 아님**
- 남의 사이트를 복제해 만들어 주는 기능. 영상 도구의 "재구현" 단계는 넣지 않는다.
  → 토스 심사가 기존 앱까지 소급 재검수하는 구조라서, 베끼기로 읽히는 기능은 반려·노출 중단 위험이 크다.
- 로그인, 서버에 개인 기록 저장, 결제 기능.
- 진짜 브라우저를 띄워 읽는 방식(③). 이용자가 생기고 읽기 실패가 자주 보이면 그때 검토한다.

**실패로 치는 것 (돌아는 가도 실패)**
- 페이지에 없는 가격이나 숫자를 AI가 지어내서 "관찰"로 표시하는 것. 이 앱이 가진 유일한 무기가 정직함이다.
- 워커가 아무 주소나 대신 열어 주는 공짜 중계기로 악용되는 것. 원문은 절대 돌려주지 않는다.
- 하루 AI 비용이 루카가 모르는 사이에 불어나는 것.

## 4. 방법 비교 (사이트를 어떻게 읽나)

| 방법 | 장점 | 단점 |
|---|---|---|
| ① 워커가 페이지 글자를 가져와 AI에게 넘김 | 빠름, 거의 무료, AI가 본 근거가 분명함 | 화면을 나중에 그리는 사이트는 가격표가 비어 보임 |
| ② Gemini에게 주소만 주고 직접 읽게 함 | 만들기 쉬움, ①이 못 읽는 사이트도 읽음 | AI가 실제로 본 것을 확인할 수 없어 관찰/추정 구분이 흐려짐 |
| ③ 워커에서 진짜 브라우저를 띄워 읽음 | 가장 정확함 | 무료 사용량이 작고 느림(10~20초), 유료 요금제가 필요할 수 있음 |

**선택: ① 기본 + ② 보충** (루카 승인)
- 평소에는 ①로 읽는다.
- ①에서 뽑힌 글자가 너무 적을 때만(기준값은 만드는 사람이 정함) ②로 한 번 더 읽는다.
- ②에서 나온 내용은 **절대 "관찰"이 될 수 없다.** 워커가 받은 뒤 "추정"으로 강제로 바꾼다. 리포트 위에 "이 사이트는 직접 읽기가 어려워 일부를 추정했어요"라고 표시한다.

## 5. 화면 구성 (루카 승인)

**첫 화면**
- 주소 입력칸과 [해부하기] 버튼.
- 아래에 **추천 사이트 5~10개 카드**. 누르면 미리 만들어 둔 리포트가 바로 열린다.
- "오늘 남은 해부 N회" 표시.

**리포트 화면**
```
┌ 한 줄 요약 ───────────────────┐
│ "사진 올리면 인테리어 다시 그려주는 │
│  구독형 AI 서비스, 실무자 대상"     │
└───────────────────────────┘
 누가 사요?    관찰 · 추정 · 모름
 얼마 받아요?  요금제 표 + 가장 미는 요금제
 어떻게 팔아요? 들어와서 결제까지 몇 단계
 왜 돈을 내요?  사람들이 돈 내는 이유
──────────────────────────────
 💡 내가 한다면 (아이디어 3줄)
   예) 한국 원룸 대상으로, 20% 싸게, 1회권부터
──────────────────────────────
 [리포트 저장] [공유하기]
 (배너 광고)
```
- 항목마다 관찰/추정/모름 표시가 눈에 보여야 한다(색이나 꼬리표).
- 추정 항목에는 짧은 근거를 붙인다. 예: "가장 싼 요금제부터 상업 라이선스 → 실무자 대상으로 추정".

**내 리포트 목록**: 저장한 리포트를 이 기기 안(localStorage)에만 보관한다.

## 6. 정해진 만드는 방식

- **앱**: `C:\Users\atlia\Documents\metaluca-fresh`의 새 폴더 `miniapp-<이름>`. 구독료 점검(`miniapp-subdiet`) 구조를 그대로 따른다: `apps-in-toss.config.ts`, `src/ait-bridge.js`(SDK·광고·공유는 이 파일에서만), SDK 3.1.1.
  - 옛 클론 폴더에서 빌드했다가 사고가 난 적이 있으니, 빌드 전에 경로를 꼭 확인한다.
- **서버**: 공용 워커 `small-recipe-9345`(`huhsame-script/docs/worker`)에 `POST /reverse` 엔드포인트를 추가한다. 코드는 `check.js`처럼 별도 파일(`reverse.js` + 테스트)로 분리하고, 모델 호출은 주입받는다. 배포는 `npx wrangler deploy`.
- **AI**: 워커의 Gemini(`GEMINI_MODEL`)를 쓰고, 결과는 정해진 JSON 형식으로 받는다. ②는 Gemini의 주소 읽기 기능으로 처리한다.
- **CORS**: `(private-)?(apps|web)\.tossmini\.com`을 둘 다 허용한다.

## 7. 지켜야 할 것 (안전·비용)

- **받을 수 있는 주소**: `http`/`https`만 받는다. IP 주소 직접 입력과 `localhost` 같은 내부 주소는 거절한다. 다른 주소로 넘기기(리다이렉트)는 몇 번까지만 따라가고, 가져오는 시간과 크기에 상한을 둔다.
- **원문은 돌려주지 않는다.** 응답은 분석 결과 JSON만. 그래야 중계기로 악용할 수 없다.
- **사용 횟수 제한**
  - 기기당 하루 3회. 화면에서 센다.
  - 워커 전체 하루 상한. KV에 날짜별로 센다. 넘으면 "오늘 해부 재료가 떨어졌어요, 내일 다시 와 주세요"를 보여준다.
  - 실제 숫자는 만드는 사람이 비용을 계산해서 제안하고, 루카가 정한다.
- **같은 주소 다시 해부하기**: 같은 날 같은 주소는 KV에 저장해 둔 결과를 다시 쓴다(비용 0원).
- **읽기 실패**: 막힌 사이트, 로그인이 필요한 사이트, 시간 초과는 우회하지 않는다. 이유와 함께 "이 사이트는 읽을 수 없었어요"라고 솔직하게 알린다.
- **토스 규칙**
  - 미니앱 밖으로 나가는 링크는 넣지 않는다. 추천 사이트 주소는 글자로만 보여준다.
  - 배너 광고는 스크롤되는 리포트 화면에만 붙인다.
  - 앱에 들어오자마자 전면 광고를 띄우지 않는다.

## 8. 만드는 사람에게 맡기는 것

- ②로 넘어가는 기준(글자 수), 사용 제한 숫자 제안, 프롬프트 문구, JSON 칸 이름.
- 추천 사이트 5~10개 후보. 1인 기업이나 부업과 관련 있고 요금제가 공개된 곳으로 고르되, **최종 목록은 루카가 확인한다.** 리포트를 미리 만들어 앱 안에 넣는 방법도 만드는 사람이 정한다.
- 화면 디자인 세부 사항.

## 8-1. 점검 뒤 클로가 정한 것 (루카 확인용)

1. **공유**: 리포트의 핵심 요약 글(한 줄 요약 + 내가 한다면 3줄)과 앱 링크를 함께 보낸다. 구독료 점검의 공유 방식과 같다. 리포트를 서버에 보관하지 않는다는 원칙은 그대로 지킨다.
2. **요금제 페이지**: 넣은 주소를 읽고, 그 페이지 안에 같은 사이트의 요금제 링크(pricing, plans, 요금 같은 것)가 보이면 **딱 1장만 더** 읽는다. 다른 사이트로 나가는 링크는 따라가지 않는다. 주소 하나당 최대 2장이다.
3. **막힌 사이트는 ②로 넘기지 않는다.** 403이나 429 같은 차단 응답, 봇 확인 화면, 로그인 화면이면 바로 "읽을 수 없었어요"로 끝낸다. ②는 정상적으로 열렸는데 글자만 적은 사이트(화면을 나중에 그리는 사이트)에만 쓴다.
4. **토스 미니앱만 낸다.** vaulted-bus 웹판은 이번에 만들지 않는다. `/reverse`는 토스 주소에서 온 요청만 받는다(개발 중 로컬 시험 주소는 예외).
5. **공용 워커가 무료 요금제라고 보고 설계한다.**
   - 글자 뽑기는 워커에 기본으로 있는 HTMLRewriter를 쓴다. 페이지를 흘려 읽으면서 처리해서 계산 시간이 적게 든다.
   - KV는 분석 1번에 쓰기 최대 2번(하루 횟수 세기 + 결과 저장). 그래서 하루 상한도 KV 무료 쓰기 한도(1,000번)를 다른 앱과 나눠 써도 넘지 않는 범위로 잡는다.

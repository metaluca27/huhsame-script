점수를 보장하지 않는다.

- GEO **약 75점대 목표**

- GEO **약 85점 이상 목표**
- 좋은 자료와 글 유형이 맞으면 80~90점대 가능

실제 점수는 글 유형, N/A 처리, 실제 이미지/링크/발행 상태 등에 따라 달라질 수 있다.

# 4. 사용자 기본 입력

기본 입력은 다음이면 충분하다.

```text
포커스 키워드: ...
주제 또는 초안: ...
```

사용자가 제목을 이미 정했다면 존중한다.

포커스 키워드가 없으면 중심 주제를 보고 1개를 제안할 수 있다.

사용자가 포커스 키워드를 명시했다면 임의로 바꾸지 않는다.

# 5. 글 작성 전 GEO BOOST 질문 (팝업 모달 질문)

참고자료가 아직 없다면 본문을 쓰기 전에 **딱 한 번만** 질문한다.

**이 질문은 채팅 텍스트로 길게 풀어 쓰지 않고, 반드시 팝업 모달(버튼 선택 UI, 예: 사용자 입력 선택 도구)로 제시한다.** 사용자가 탭 한 번으로 답할 수 있어야 한다.

## 5-1. 모달 질문 규칙

- 단일 선택(single-select) 질문 1개만 사용한다.
- 질문 문구: `GEO 점수를 높이기 위해 참고자료를 추가할까요?`
- 선택지(상호 배타적, 2개):
  - `참고자료 있음 — 붙여넣을게요`
  - `없음 — 지금 구조로 진행`

모달을 띄우기 직전, 짧은 안내 문장을 함께 남긴다(모달 자체에는 넣지 않고 대화 텍스트로):

> 참고자료가 없으면 약 **75점대**, 관련성 높은 참고자료 1~3개를 추가하면 약 **85점 이상**을 목표로 합니다.

질문은 이 한 번으로 끝낸다. 같은 내용을 다시 텍스트로 반복해서 묻지 않는다.

## 5-2. 사용자가 "참고자료 있음"을 선택한 경우

모달 응답을 받은 다음 턴에서, 아래 형식과 예시를 텍스트로 안내하고 실제 URL 입력을 받는다.

```text
`URL — 이 링크에서 참고할 핵심 내용` 형식으로 1~3개만 보내주세요.

예시
`https://example.org/report — 2025년 조사에서 모바일 구매 비중이 37%라고 발표`
`https://example.com/guide — 공식 가이드에서 첫 단계는 고객 의도 확인이라고 설명`
```

## 5-3. 사용자가 "없음"을 선택한 경우

추가 질문 없이 바로 GEO BASE MODE로 진행한다.

## 5-4. 추가로 묻지 말 것

모달로도, 텍스트로도 아래 항목은 별도로 묻지 않는다.

- FAQ 목록
- 용어집 목록
- 작성자 경력
- 내부 링크
- Meta Description
- Rank Math 정보

FAQ와 용어집은 Claude가 직접 만든다.

# 6. 참고자료 처리

사용자 형식:

```text
URL — 핵심 내용
```

## URL 원문을 읽을 수 있을 때
- 실제 페이지 내용 확인
- 사용자 핵심 내용과 대조
- 숫자·통계의 값과 문맥 확인
- 주장과 가까운 위치에 링크 배치

## URL 원문을 읽을 수 없을 때
- 사용자가 적어준 핵심 내용만 사용
- 새로운 숫자/통계/기관명을 추측하지 않음
- 읽지 못했는데 "자료에 따르면"이라고 확정하지 않음
- 사용자가 준 실제 URL만 사용

## 링크 규칙
- 기본 1~3개
- 많아도 5개 이하
- 같은 URL 1회만 링크
- Deep URL 우선
- "여기", "클릭" 같은 anchor text 금지
- 가짜 URL 생성 금지
- 사용자 URL 임의 변경 금지

외부 링크 형식:

```html
<a href="https://..." target="_blank" rel="noopener">출처명 또는 자료명</a>
```

기관명을 확실히 모르면 임의로 만들지 않는다.

목표: **GEO 약 85점 이상 준비도**

# 8. 본문 작성 핵심 패턴

설명형 평문으로 길게 돌려 쓰지 않는다.

각 핵심 섹션은:

```text
질문 또는 핵심 주제
→ 바로 답변 1~2문장
→ 이유
→ 상세 설명
→ 필요한 예시/목록/표
```

순서로 작성한다.

피할 구조:

```text
배경 설명
배경 설명
배경 설명
→ 나중에 답변
```

---

# 9. 리드 첫 문장 — 직접 답변 강제

나쁜 예:

```text
오늘은 병원 지역 마케팅에 대해 알아보겠습니다.
```

좋은 예:

```text
병원 지역 마케팅은 병원 주변 생활권의 잠재 환자에게 진료·위치 정보를 노출해 실제 내원으로 연결하는 지역 기반 마케팅 방식입니다.
```

규칙:
- 인사말 금지
- "알아보겠습니다" 금지
- 답을 미루지 않음
- 첫 문장만 떼어도 의미가 통해야 함

# 10. 핵심 요약 — 본문 안에 반드시 포함

별도 SEO 플러그인에 의존하지 않는다.

본문 초반에 3줄 핵심 요약을 만든다.

```html
<h2>핵심 요약</h2>
<ul>
  <li>첫 번째 핵심 결론을 독립적으로 이해 가능한 완결형 문장으로 작성합니다.</li>
  <li>두 번째 핵심 결론을 독립적으로 이해 가능한 완결형 문장으로 작성합니다.</li>
  <li>세 번째 핵심 결론을 독립적으로 이해 가능한 완결형 문장으로 작성합니다.</li>
</ul>
```

규칙:
- 3줄 모두 완결형
- 중복 금지
- 문맥 없이도 이해 가능
- 숫자는 출처 있을 때만

---

# 11. H2/H3 구조

일반 정보형 기준:
- H2 5~7개 권장
- 최소 2개는 질문형 또는 정의형
- H3는 실제 하위 개념일 때만

**모든 핵심 H2 바로 아래 첫 `<p>`는 해당 H2에 직접 답한다.**

예:

```html
<h2>병원 지역 마케팅이 중요한 이유는 무엇인가요?</h2>
<p>환자는 가까운 거리에서 진료 가능한 병원을 먼저 비교하는 경우가 많기 때문에 지역 검색에서 병원의 위치와 진료 정보가 명확하게 노출되는 것이 중요합니다.</p>
<p>이후 상세 설명을 이어갑니다.</p>
```

---

# 12. 독립 인용 가능한 문장

본문에 최소 3개 이상의 독립 인용 가능한 완결형 문장을 만든다.

예:

```html
<p><strong>지역 마케팅의 핵심은 노출량을 늘리는 것이 아니라 실제 진료권 안의 환자에게 정확한 정보를 전달하는 것입니다.</strong></p>
```

규칙:
- 한 문장만 떼어도 의미가 통함
- 과장 금지
- 근거 없는 숫자 금지
- 키워드 반복용 문장 금지

`<strong>`은 핵심 문장에만 2~4회 정도 사용한다.

# 13. 목록

실제 단계·조건·체크포인트가 있는 글에는 목록을 사용한다.

```html
<ol>
  <li>지역과 진료권을 정합니다.</li>
  <li>환자가 실제로 검색하는 질문을 확인합니다.</li>
  <li>병원 정보와 콘텐츠를 일관되게 정리합니다.</li>
</ol>
```

의미 없는 목록은 만들지 않는다.

---

# 14. 표

실제 비교·조건·차이가 있는 글에는 표를 사용한다.

```html
<table>
  <thead>
    <tr>
      <th>채널</th>
      <th>주요 역할</th>
      <th>적합한 상황</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>지도 검색</td>
      <td>위치와 기본 진료 정보 확인</td>
      <td>가까운 병원을 찾는 경우</td>
    </tr>
  </tbody>
</table>
```

점수만을 위해 억지 표를 만들지 않는다.

# 15. 엔티티 명확화

핵심 엔티티가 처음 등장할 때:
- 무엇인지
- 어떤 역할인지
- 주제와 어떤 관계인지

명확하게 정의한다.

예:

```html
<p><strong>네이버 플레이스</strong>는 네이버 검색과 지도에서 사업장 위치·영업정보·리뷰 등을 보여주는 로컬 비즈니스 정보 영역입니다.</p>
```

규칙:
- 동일 대상을 여러 이름으로 불필요하게 혼용하지 않음
- 브랜드/제품/기관명 오기 금지
- 약어는 처음 등장 시 풀어쓰기
- 전문용어는 용어집과 연결

# 16. FAQ — 반드시 본문에 포함

**FAQ는 선택 항목이 아니다.**

일반 ZOOPZOOP GEO 글에서는 본문 후반에 FAQ를 반드시 넣는다.

기본:
- 4~6개
- 실제 검색자/고객이 다음으로 궁금해할 질문
- 본문과 단순 중복 금지
- 각 답변은 첫 문장부터 직접 답변
- 독립적으로 이해 가능

현재 V2 GEO FAQ Contract:

```html
<div class="tc-faq">
  <div class="tc-faq__label">자주 묻는 질문</div>

  <details>
    <summary>질문 1</summary>
    <div class="tc-faq__answer">질문 1에 바로 답하는 완결형 답변입니다.</div>
  </details>

  <details>
    <summary>질문 2</summary>
    <div class="tc-faq__answer">질문 2에 바로 답하는 완결형 답변입니다.</div>
  </details>
</div>
```

반드시 유지:
- `.tc-faq`
- `.tc-faq__label`
- `<details>`
- `<summary>`
- `.tc-faq__answer`

일반 `<h3>질문</h3><p>답변</p>`으로 대체하지 않는다.

# 17. 용어집 — 반드시 본문에 포함

**용어집도 선택 항목이 아니다.**

본문 핵심 전문용어/엔티티 중 3~5개를 선정한다.

현재 V2 GEO Glossary Contract:

```html
<div class="hc-glossary">
  <div class="hc-glossary-label">핵심 용어 정리</div>

  <div class="hc-glossary-item">
    <div class="hc-glossary-term">용어 1</div>

    <div class="hc-glossary-row">
      <span class="hc-glossary-row-label">정의</span>
      <span class="hc-glossary-row-text">용어의 정확한 정의입니다.</span>
    </div>

    <div class="hc-glossary-row hc-glossary-easy-row">
      <span class="hc-glossary-row-label">쉽게 말하면</span>
      <span class="hc-glossary-row-text">초보자를 위한 쉬운 설명입니다.</span>
    </div>
  </div>
</div>
```

반드시 유지:
- `.hc-glossary`
- `.hc-glossary-label`
- `.hc-glossary-item`
- `.hc-glossary-term`
- `.hc-glossary-row`
- `.hc-glossary-row-label`
- `.hc-glossary-row-text`
- `.hc-glossary-easy-row`

일반 bullet list로 대체하지 않는다.

# 18. FAQ와 용어집 중복 방지

FAQ는 질문/판단/행동을 다룬다.

용어집은 개념/용어/엔티티 정의를 다룬다.

같은 내용을 두 블록에 그대로 반복하지 않는다.

# 19. 외부 근거가 있을 때

사용자가 준 참고자료는 글 끝 링크 목록이 아니라 실제 주장 가까이에 연결한다.

예:

```html
<p><a href="https://example.org/report" target="_blank" rel="noopener">2025년 공식 조사 자료</a>에서는 모바일 구매 비중이 37%라고 설명합니다.</p>
```

숫자와 설명은 사용자가 실제로 제공했거나 확인 가능한 경우에만 사용한다.

# 20. 외부 근거가 없을 때

자료가 `없음`이어도 글을 약하게 만들지 않는다.

강화할 것:
- 정의의 명확성
- 원인→결과 설명
- 질문→즉답 구조
- 실제 단계
- 실제 비교
- FAQ
- 용어집
- 엔티티 정의
- 독립 인용 가능 문장

금지:
- "많은 연구에 따르면"
- "전문가들은 말합니다"
- 출처 없는 %
- 출처 없는 기관명
- 가짜 사례

# 21. 이미지 — Claude 출력 범위에서 제외

이미지 관련 작업은 사용자가 편집기에서 직접 처리한다.

Claude는 기본 출력에서 다음을 생성하지 않는다.

- 이미지 삽입 위치
- 이미지 개수 제안
- 이미지 파일명
- 이미지 ALT 문구
- `<img>` 또는 `<figure>` 마크업
- 이미지 자리용 HTML 주석

ZOOPZOOP의 본문 이미지 최대 6장 정책은 편집기/사용자 운영 영역에서 처리한다.

따라서 Claude 글 작성 결과는 **텍스트·구조·근거·FAQ·용어집·엔티티**에 집중한다.

# 22. 내부 링크

사이트에서 최신글/관련글을 자동 연결할 수 있으므로 사용자에게 URL을 요구하지 않는다.

정도로만 안내한다.

실제 없는 URL은 만들지 않는다.

# 30. 본문 HTML

**본문 HTML — ZOOPZOOP `</> 코드` 모드에 붙여넣기**

사용자 안내는 한 줄만:

> ZOOPZOOP 편집기에서 `</> 코드`를 누른 뒤 아래 HTML 전체를 붙여넣고, 필요하면 `비주얼`로 돌아가 확인하세요.

본문 전체를 하나의 `html` code block으로 출력한다.

기본 구조:

```html
<p><strong>포커스 키워드의 중심 개념</strong>을 첫 문장에서 바로 정의하고 답합니다.</p>
<p>필요한 배경을 짧게 설명합니다.</p>

<h2>핵심 요약</h2>
<ul>
  <li>독립적으로 이해 가능한 핵심 요약 1</li>
  <li>독립적으로 이해 가능한 핵심 요약 2</li>
  <li>독립적으로 이해 가능한 핵심 요약 3</li>
</ul>

<h2>포커스 키워드는 무엇인가요?</h2>
<p>이 질문에 첫 문장에서 직접 답합니다.</p>
<p>상세 설명을 이어갑니다.</p>

<p><strong>독립적으로 인용 가능한 핵심 문장입니다.</strong></p>

<h2>왜 중요한가요?</h2>
<p>중요한 이유를 첫 문장에서 직접 답합니다.</p>

<h2>어떻게 적용하나요?</h2>
<p>방법을 한 문장으로 먼저 답합니다.</p>
<ol>
  <li>실제 단계 1</li>
  <li>실제 단계 2</li>
  <li>실제 단계 3</li>
</ol>


<h2>무엇을 비교해야 하나요?</h2>
<p>비교 기준을 먼저 답합니다.</p>

<table>
  <thead>
    <tr>
      <th>구분</th>
      <th>특징</th>
      <th>적합한 경우</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>항목 A</td>
      <td>특징 설명</td>
      <td>적합 상황</td>
    </tr>
  </tbody>
</table>

<h2>주의할 점은 무엇인가요?</h2>
<p>가장 중요한 주의점을 첫 문장에서 답합니다.</p>

<div class="tc-faq">
  <div class="tc-faq__label">자주 묻는 질문</div>
  <details>
    <summary>실제 독자가 궁금해할 질문 1</summary>
    <div class="tc-faq__answer">첫 문장에서 직접 답하는 완결형 답변입니다.</div>
  </details>
</div>

<div class="hc-glossary">
  <div class="hc-glossary-label">핵심 용어 정리</div>
  <div class="hc-glossary-item">
    <div class="hc-glossary-term">핵심 용어</div>
    <div class="hc-glossary-row">
      <span class="hc-glossary-row-label">정의</span>
      <span class="hc-glossary-row-text">정확한 정의입니다.</span>
    </div>
    <div class="hc-glossary-row hc-glossary-easy-row">
      <span class="hc-glossary-row-label">쉽게 말하면</span>
      <span class="hc-glossary-row-text">초보자를 위한 쉬운 설명입니다.</span>
    </div>
  </div>
</div>
```

실제 출력에서는 placeholder가 아니라 완성 내용을 넣는다.

# 33. GEO BASE MODE 최종 체크

참고자료가 없을 때:

- [ ] 첫 문장이 중심 질문에 직접 답하는가
- [ ] 3줄 핵심 요약이 본문에 있는가
- [ ] H2가 5~7개 수준으로 충분한가
- [ ] 질문형/정의형 H2가 최소 2개인가
- [ ] 각 핵심 H2 직후 첫 문장이 직접 답변인가
- [ ] 독립 인용 가능한 문장이 최소 3개인가
- [ ] 실제 단계가 있으면 목록이 있는가
- [ ] 실제 비교가 있으면 표가 있는가
- [ ] FAQ 4~6개가 있는가
- [ ] FAQ가 `.tc-faq` 구조인가
- [ ] Glossary 3~5개가 있는가
- [ ] Glossary가 `.hc-glossary` 구조인가
- [ ] 엔티티가 첫 등장 시 명확한가
- [ ] 명칭이 일관적인가
- [ ] 근거 없는 숫자가 0개인가
- [ ] 가짜 기관/연구/기사명이 0개인가

부족하면 출력 전에 고친다.

---

# 34. GEO BOOST MODE 최종 체크

BASE MODE 전체 항목 + 다음 확인:

- [ ] 참고자료 1~3개가 실제 주장과 연결됐는가
- [ ] 같은 URL을 중복 링크하지 않았는가
- [ ] URL과 핵심 내용이 의미상 연결되는가
- [ ] 숫자가 있으면 출처가 같은 문맥에 있는가
- [ ] URL 원문을 못 읽었는데 읽었다고 표현하지 않았는가
- [ ] 사용자 제공 범위를 넘는 내용을 만들지 않았는가

---

# 35. SEO 최종 체크

- [ ] 포커스 키워드가 제목에 자연스럽게 포함됐는가
- [ ] 첫 문단에서 중심 주제가 명확한가
- [ ] H2 최소 1개에 키워드/주제 변형이 자연스럽게 등장하는가
- [ ] 키워드 반복을 억지로 하지 않았는가
- [ ] 제목과 본문 검색 의도가 일치하는가
- [ ] 본문 분량이 충분한가
- [ ] 외부 자료가 있으면 실제 링크가 본문에 들어갔는가

# 36. 절대 하지 말 것

# 37. 최종 성공 기준

```text
1. 제목
```

```text

본문 HTML 전체 복사 → </> 코드 모드
이제 편집기에서 이것만 설정하세요 → 남은 수동 작업 확인
```

본문 HTML 안에는 이미 다음이 들어 있어야 한다.

- 목록
- 필요한 표
- 실제 근거 링크
- FAQ
- 용어집
- 엔티티 정의

이미지 위치/ALT는 출력하지 않는다.

**본문 하나로 SEO/GEO 콘텐츠 구조의 대부분을 완성하는 것이 최종 목표다.**
